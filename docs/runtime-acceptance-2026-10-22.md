## 真实语音证据

沿用本机已配置的 `qwen3.8-omni-flash-realtime`，仅通过应用既有语音接口使用凭证。凭证未输出、未复制到其他配置，也没有替换或保存新凭证。

Windows 本地语音合成输出 16 kHz、单声道 PCM16，时长 **7.27 秒**。发送的虚构练习句与收到的转写相同：

> Hello. I would like to practice ordering a cup of tea. Please ask me one short question.

AI 返回文字 **What kind of tea would you like?**，以及 **2.00 秒**、24 kHz、单声道 PCM16。检查了 PCM 长度、采样率和完整性，没有播放声音，因此不把此结果当作扬声器音质验收。

服务返回用量：input **776**、output **35**、total **811 tokens**。同 ID 重放的整个 JSON 与首次返回一致。单测另有上游发送次数断言；真实 HTTP 重放一致性本身不单独证明服务商账单只计费一次。

回复 PCM SHA-256：`b0e5fe873a72cb820a42efcf33a88f41617d8df6bd66e5a84530af26947b742b`。原始音频与本机验收脚本留在 Git 忽略的验证目录，不进入提交、学习备份或分享包。

浏览器使用独立 origin `http://127.0.0.1:5187/`，原有 `5177` 页面和数据不变。新站点初始化完成后，通过语音消息页面识别到已有千问服务配置；点击开始后出现“等待你的语音消息”，点击结束后出现“练习已结束”，设置恢复可编辑。没有申请麦克风权限。结束空会话不制造学习记录或 FSRS 证据。

## 启动脚本证据

检查了 `5.3.2` 分享包生成目录中的两个实际 `.command` 文件，以及当前源码生成的桌面开发快捷方式：

- 三份脚本均通过 `bash -n`。
- 分享服务已运行时，脚本直接打开默认 `4173` 地址，不启动第二个 Node 进程。
- 服务未运行时，启动 `node ./server.mjs`，就绪后打开页面。
- “一键启动（终端）”可以转交到实际分享启动脚本。
- 开发快捷方式分别通过复用与启动路径；项目目录包含空格、单引号及中文，仍正确传入路径和 URL。

上述分支执行使用真实 Bash；`curl`、`open`、`node`、`npm`、`xattr`、`osascript` 被本地测试替身替换。它证明脚本语法、引号与控制流程，不能证明 macOS 的 PATH、Node 安装、隔离属性处理、Finder 双击或系统弹窗正常。分享包实际 Node 服务及资源检查另见[交付验收](seed-rebuild-review-2026-10-22.md)。
