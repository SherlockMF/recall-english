# 非真机收尾实施计划

**目标：** 完成已授权的浏览器自动化、跨平台 CI、加载优化和 lint 整理；保留真机硬件验收边界。

**方案：** 生产构建与既有分享服务作为端到端测试目标，Chromium 使用独立上下文及本机端口。所有学习、编辑与备份操作只作用于测试浏览器；测试拒绝外部服务调用，不读取或复制真实凭证。保留现有数据模型、词库和学习规则。

**约束：** 不推送、部署或发布；不调用收费 AI、不申请麦克风；只增加运行端到端测试所必需的开发依赖。性能以相同浏览器与真实生产资源的前后测量为依据，区分静态字节与本机耗时。不得关闭 lint 规则来掩盖问题；有意保留的模式以局部理由记录。

- [x] 添加 Playwright 配置与关键流程测试：空库启动、回忆保存与重开、义项编辑与隔离、备份下载与恢复、首次/再次资源加载。先运行未优化版本，保存性能基线。
- [x] CI 使用 Ubuntu、Windows、macOS 矩阵，运行单测、构建、分享包与浏览器流程；失败保存诊断产物。依据官方文档检查语法，本机不冒充远端执行。
- [x] 根据基线按需加载重页面及可选模块，回归现有组件与端到端流程，比较首屏 JS、首次启动和切页数据。
- [x] 按当前 lint 诊断分类修正安全、错误保留、依赖与低风险问题；验证全量单测、端到端、构建、词库及新分享包，完成复核、交付记录和本地提交。

涉及文件以 `playwright.config.ts`、`e2e/`、`package.json`/lockfile、`.github/workflows/ci.yml`、`src/App.tsx` 及实际出现 lint 的文件为准；不进行无关架构重构。
